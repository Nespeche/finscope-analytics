# Informe de arquitectura de automatización — v0.12

## Arquitectura conservada

- React/Vite/TypeScript; Web Worker para normalización/cálculo.
- Pages estático; Worker/Hono/Zod como gateway ligero.
- D1 mínimo, no sensible y fuera del camino crítico personal.
- IndexedDB opcional, `session_only` por defecto y consentimiento explícito.
- CI gratuito para snapshots públicos; Cron solo detección/orquestación ligera.

## Dos modos, un motor

| Dimensión | Personal | Público automatizado |
|---|---|---|
| Activación | apertura/reanudación autorizada, detección local o botón | scheduler/CI y reconciliación |
| Credencial de mercado | BYO-key efímera/protegida | solo si policy oficial habilita central |
| Cálculo | Web Worker | mismo paquete TypeScript versionado en CI |
| Persistencia | sesión; IndexedDB con consentimiento | snapshots públicos atómicos en D1 |
| Camino crítico | navegador | CI/gateway, sin navegador abierto |
| Resultado | snapshot local | snapshot público activo |

## Restricción operativa

No existe paso externo manual. Una decisión humana se expresa mediante UI; la aplicación valida el input y reanuda el pipeline. La ejecución de GitHub Actions o Cron es automática y no se presenta al usuario como tarea manual.

## Seguridad ante fallos

Toda ejecución es idempotente. El candidato queda separado del snapshot activo. Un fallo, cancelación o quality gate negativo conserva la última versión válida y bloquea solo capacidades dependientes.
