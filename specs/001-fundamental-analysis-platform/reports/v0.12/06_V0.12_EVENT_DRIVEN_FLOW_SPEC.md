# Especificación del flujo event-driven — v0.12

## Eventos

`new_filing`, `amended_filing`, `restatement_detected`, `new_market_close`, `market_series_corrected`, `mapping_version_changed`, `metric_definition_changed`, `insight_rule_changed`, `policy_changed`, `manual_refresh`.

## Estados

`detected → queued → acquiring → sanitizing → normalizing → validating → analyzing → quality_check → ready_to_publish → published`.

Ramas terminales/controladas: `partial`, `awaiting_market_data`, `needs_review`, `failed`, `cancelled`, `superseded`.

## Idempotencia

- SEC: `issuerId + accessionNumber + form + acceptedAt`.
- Mercado: `instrumentId + mic + sessionDate + providerId + adjustmentStatus`.
- Cambios normativos: tipo + versión nueva + scope afectado.

## SEC extremo a extremo

Detección → event → deduplicación → submissions/Company Facts → sanitización → normalización → períodos/amendments/restatements → conceptos/derivaciones → métricas → confianza → reglas/síntesis → candidato → quality gate → activación atómica → ETag/cache.

## Mercado personal

Registry determina última sesión completada → compara último cierre local → adquiere solo faltante → normaliza → recalcula consumidores → persiste solo si autorizado. Sin credencial válida se preserva el estado y se ofrece UI.

## Mercado público

Solo existe cuando `centralMarketUpdateEnabled=true` por policy efectiva. Sin autorización de almacenamiento/display/retención/redistribución, permanece false y no se simula actualización central.
