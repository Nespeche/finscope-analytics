## NF-001 — AC-071 oracle contains non-determinate expression

| Field | Value |
|-------|-------|
| Finding ID | NF-001 |
| Severity | MINOR |
| Domain | acceptance-criteria |
| File | `specs/001-fundamental-analysis-platform/definitions/acceptance-criteria-catalog.json` |
| Criterion ID | AC-071 |
| Discovered | v0.17 independent checklist |

### Description

`AC-071` declares `"oracleKind": "single_exact_oracle"` but its oracle text reads:

```
"oracle": "control aria-busy/disabled as appropriate"
```

The phrase **"as appropriate"** is a non-determinate qualifier. A `single_exact_oracle` must specify a single deterministic expected outcome that can be mechanically verified by a test runner. The expression "as appropriate" introduces evaluator discretion, making the oracle non-exact.

### Impact

- **Automated test generation**: a test runner cannot generate a binary pass/fail assertion from "as appropriate." The criterion is not automatable as specified.
- **Scope**: limited to UI accessibility state management. Does not affect any financial computation, XBRL acquisition, quality model, fingerprint, or metric logic.
- **No other criteria affected**: all remaining 83 of 84 criteria have determinate oracle texts.

### Relationship to V15-B09

V15-B09 addressed systemic oracle vagueness across multiple criteria. That systemic issue is resolved (83/84 criteria are now determinate). NF-001 represents a single residual instance that was not remediated in v0.16.

V15-B09 is classified CLOSED (systemic issue resolved). NF-001 is a new MINOR finding.

### Required Remediation

The oracle for AC-071 must be rewritten to specify a single exact expected state, for example:
- "aria-busy=true while acquisition is in-flight; aria-disabled=true when pipeline is in failed or cancelled state"

The remediation must not introduce new ambiguities. The `oracleKind` must remain `single_exact_oracle` with a determinate oracle text.

### Effect on Approval

NF-001 is **MINOR**. Per the approval rule, APPROVED_FOR_TASKS requires only that no new BLOCKER or MAJOR findings be opened. NF-001 does not block approval.

NF-001 must be addressed in the next remediation cycle (v0.18 or equivalent) before the criterion can be used for automated test generation.
