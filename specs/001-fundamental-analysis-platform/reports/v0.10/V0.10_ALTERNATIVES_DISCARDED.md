# Matriz de alternativas descartadas — v0.10

| Bloqueante | Alternativa descartada | Ventaja | Razón de descarte |
|---|---|---|---|
| B01 | Modelo de dominio sin frontera raw explícita | menor cantidad de nombres conceptuales | no modela respuestas externas variables ni asegura destrucción del raw |
| B01 | OpenAPI como autoridad primaria | contrato visible y validable | acopla dominio al transporte HTTP y no cubre CSV/IndexedDB como consumidores locales |
| B02 | Solo clase económica única | máximo conservadurismo | reduce innecesariamente utilidad para multiclase/ADR verificables |
| B02 | Construir total de emisor en todos los casos | mayor cobertura aparente | obliga a inferir clases, precios, ratios o FX cuando faltan datos |
| B03 | Modelo categórico puro | simple de explicar | no ofrece score total/testable por resultado ni caps graduados |
| B03 | Modelo numérico puro | fácil de ordenar | permite que un promedio alto compense incompatibilidad financiera crítica |
| B04 | Enum global | una sola lista | mezcla responsabilidades y permite combinaciones semánticas imposibles |
| B04 | Enums separados sin discriminación | mejora vocabulario | no impide `available` con value null o estados incompatibles en contratos |
| B05 | Sin fallback | costo mínimo | degrada Company Facts grandes/incompletos aun cuando pocas llamadas resolverían métricas |
| B05 | Bulk/preprocesamiento | cobertura amplia | contradice on-demand/browser-first, amplía storage, batch y operación central |

## Criterio común

Se descartó toda alternativa que requiriera inferencias silenciosas, servicios pagos, batch global, FX automático, segunda fuente canónica o ampliación implícita del MVP.
